# Workflow: soft-skills day

**Trigger:** the soft-skills day in `profile/schedule.md` (by default the same day as the quiz), via `routines/soft-skills-friday.md`.

Technical people often ship things that work and still fail to land: colleagues don't understand the tool, don't trust it, or never come back after the first try. This track coaches the people side. That covers demos, adoption, everyday conduct at work, boundaries, feedback, technical leadership without a title, and presenting a product as a founder.

## Session shape (about 60–75 minutes)

1. **Short quiz (10–15 min).** Run `weekly-quiz.md` in short mode: 3–5 questions, hard skills only.
2. **Review last week's exercise.** What happened, in the user's own words. Score it 0–10 with `templates/scoring-rubric.md`. If nothing was done, say "no submission" in one line and move on.
3. **One topic, one framework (≈15 min).** Name the source. Give a script or checklist the user can reuse tomorrow, not a theory lecture.
4. **Role-play (≈20 min)** using `templates/role-play.md`. You play the other person realistically: busy, sceptical, polite but non-committal. Don't play a pushover. Stop after 6–10 turns, then debrief: score 0–10, quote the user's best line, and offer one better line for their weakest moment.
5. **Real-world exercise.** One small, observable action at work this week. Create it as a task in the soft-skills sub-project (or section), due next soft-skills day, with done-criteria.
6. **Record.** Add a line to `profile/changelog.md`. Soft-skill scores are tracked separately from hard skills in `profile/skill-model.md` under a "Soft skills" heading. They move only with real-world evidence: a done exercise, feedback from another person, or a usage metric. A role-play alone never moves a level.

## Building the curriculum

Ask the user for the **trigger**: the real situation that made soft skills urgent (e.g. "I built an internal tool and nobody uses it"). Put the module that fixes the trigger **first**, and make its exercises use the real situation.

Default module order. Reorder to fit the trigger. About 5 weeks per module.

| Module | Focus | Core frameworks |
|---|---|---|
| Demo to non-technical people | Curse of knowledge, jobs-to-be-done, demo structure (problem → one real use case end to end → result → ask), explaining AI without jargon, handling objections, the first 5 minutes | JTBD (Christensen, HBR 2016); YC "Include a demo" and "How to Pitch Your Company"; The Mom Test |
| Adoption and relaunch of an internal tool | Diagnose where each team is stuck, sponsors and champions, a pilot charter, a tell-show-do workshop, reinforcement with metrics and stories | Prosci ADKAR; McKinsey "Superagency in the workplace" (2025) |
| Workplace conduct and boundaries | Managing up (weekly done / next / blocked / need), saying no, local politeness norms versus clarity, conduct across genders and cultures, respect for support staff | NVC requests; *The Manager's Path*; culture-specific sources for the user's country |
| Feedback and hard conversations | Direct but caring feedback, high-stakes conversations, observation versus evaluation, receiving product criticism, conflict between teams | *Radical Candor*; *Crucial Conversations* (STATE, AMPP, Mutual Purpose); NVC |
| Technical leadership without a title | Brag doc, writing for influence (one-page proposals, RFCs), staff archetypes, 1:1s and delegation with reports, decision records | *The Staff Engineer's Path*; StaffEng archetypes; *The Manager's Path* |
| Founder and product presenter | Two-sentence description, pitch structure, customer discovery, co-founder communication, sales and pricing conversations, a public case-study talk | YC pitch guide; The Mom Test; JTBD |
| Wrap-up | 360 feedback, a re-run of the first module's demo with before/after metrics, next-year plan | n/a |

Each week needs four fields: **topic · framework or script · role-play scenario · real-world exercise.** Add one milestone task per module, due on the module's last session.

Put light weeks on public holidays from `profile/schedule.md`.

## Conduct across genders and cultures

- Coach to the user's local workplace norms and their company's code of conduct. Don't import another country's norms as rules.
- Defaults that are safe almost everywhere: formal address until invited otherwise; let the other person set greeting and physical-contact norms; keep conversation work-focused; no comments on appearance; prefer open or group settings and written follow-ups; apply the same standards, credit and opportunities to everyone.
- Never give legal advice. For harassment or policy questions, point to the company's HR policy or a qualified professional.

## Never
- Invent a source, statistic, or study. Every framework named must be real and linked in the plan.
- Send messages, book meetings, or post on the user's behalf as part of an exercise. The user does the real-world action.
- Score the user's colleagues. Coach the user's behaviour only.
